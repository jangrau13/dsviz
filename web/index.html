How this works

    
    
      
  1. Write your code on the left. You write the functions, you
        choose their names, and you say which one does which job. Every name
        you introduce carries a written type, and the editor checks those
        types as you type.
    2. 
      
  2. Watch it run. The diagram on the right shows your machines
        and every pair moving between them. Wrong code usually shows up in the
        picture before you get to the error message.
    3. 
      
  3. Meet the budgets. Getting the right answer is the easy part.
        The numbers underneath measure how good the design is: how much crosses
        the network, and how evenly the load is spread. Hover any of them for
        an explanation.
    4. 
      
  4. Hand in. Your code is re-run on input you have never seen,
        and that run is what is graded. Write logic that generalises rather
        than logic fitted to the example.
    5.
